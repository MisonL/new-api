# new-api 正式升级计划

基线版本：`4527d7666-litefix2`（2026-09-08，镜像 `new-api-local:prod-codex-lite-4527d7666-litefix2`）  
候选 HEAD：`0440239e5`（领先 691 个提交）

## 1. 升级要点

### 1.1 迁移不中断的三项数据变更

| 变更 | 生产线当前状态 | 影响 |
|---|---|---|
| models/vendors 部分唯一索引 | 生产 PG 仍为旧复合唯一索引 `uk_model_name_delete_at` / `uk_vendor_name_delete_at` | `migrateDB()` 会先建 `uk_model_name`(partial)，再 DROP 旧索引 |
| quota_data 唯一索引 | 已有 `quota_data_pkey`(id)，新增唯一索引由 `migrateQuotaDataUniqueIndex()` 负责 | 迁移先合并存量重复桶再建索引，不会报错 |
| 日志索引并发重建 | 生产 `logs` 表 268 万行，缺失索引由 `ensureLogIndexesMatchModel` 以 `CONCURRENTLY` 建 | 不锁表不阻塞写入 |

三项迁移按顺序排在 `migrateDB()` 里，启动时自动执行。`CONCURRENTLY` 索引不允许在事务内执行，`ensureLogIndexesMatchModel` 在事务外先跑，其余迁移各自有幂等标记。

### 1.2 运行时用户提升

现行镜像进程运行在 root 下（基线版本早于非 root 化提交 `a6a0d5cf5`）。候选镜像入口脚本 `entrypoint.sh` 以 root 启动，处理运行时目录后降权到 uid 1000。挂载的 data/logs 目录需要宿主侧可写：`chown 1000:1000`。

### 1.3 路线开关默认值核对

| 开关 | 生产当前值 | compose 默认值 | 影响 |
|---|---|---|---|
| `CHANNEL_ROUTING_V2_ENABLED` | false | false | 保持一致，ge |
| `CHANNEL_ROUTING_V2_STRICT_WRITES` | (空字符串) | (强制为空) | 保持一致 |
| `CHANNEL_CONCURRENCY_STRICT` | true | true | 保持一致 |
| `TRUSTED_PROXIES` | 未设（容器内为空） | `:-}` 留给 `.env` 设 | 当前为空=不信任任何转发头，升级后同 |
| `BATCH_UPDATE_ENABLED` | true | true | 保持一致 |

关键差异在于生产镜像的硬编码版 `new-api` 用户而非 `newapi:1000`，且不经历 `entrypoint.sh` 降权流程。

## 3. 已知风险

- **构建缓存争用**：`go build ./...` 在两会话并发时可能被缓存锁挂 15+, `scripts/build-docker-local.sh` 在容器内构建，不受影响
- **`model` 偶发 shuffle 失败**：可用 `-count=5` 再次本模式确认与本轮改动无关的既有偶发失败，门禁不依赖 `-shuffle`
