## 1. 升级要点

### 1.1 启动迁移（全部自动执行，按 `model/main.go` 的顺序）

`migrateDB()` 的固定顺序：`migrateSubscriptionPlanPriceAmount` → `migrateTokenModelLimitsToText` → `migrateRequestHeaderStrategyStateScopeTypeLength` → `ensureLogIndexesMatchModel` → 大 `AutoMigrate` → `migrateChannelPinOrder` → `migrateRetryStatusCodesLegacyDefault` → `migratePrefillGroupTable` → `migrateModelMetaUniqueIndex` → `migrateVendorMetaUniqueIndex` → `migrateQuotaDataUniqueIndex` → `migrateResponsesCompactModeAuto` → `SubscriptionPlan`。`migrateLOGDB()` 另有 `ensureLogIndexesMatchModel(LOG_DB)`、`AutoMigrate(&Log{})`、`migrateLogIndexCleanup`。

与本轮改动直接相关的三项：

| 变更 | 生产当前状态（2026-11-04 实测） | 行为 |
|---|---|---|
| models/vendors 名称唯一性 | 仍是旧复合唯一索引 `uk_model_name_delete_at`、`uk_vendor_name_delete_at`，没有 `uk_model_name` / `uk_vendor_name` | 先建部分唯一索引（`WHERE deleted_at IS NULL`），再 DROP 旧复合索引 |
| quota_data 唯一索引 | 只有 `quota_data_pkey` | 迁移先在事务内合并存量重复桶，再建唯一索引 |
| logs 缺失索引 | `logs` 2679682 行 | `ensureLogIndexesMatchModel` 用 `CREATE INDEX CONCURRENTLY`，在事务外先建，不阻塞写入 |

旧的复合唯一索引对未删除行没有约束力（`deleted_at` 为 NULL 时互不相等），删除不会放松任何现存的唯一性约束。

### 1.2 运行时用户提升

现行镜像进程以 root 运行（`docker top new-api` 的 `USER` 为 `root`），因为基线镜像早于非 root 化提交 `a6a0d5cf5`。

候选镜像入口 `deploy/docker/entrypoint.sh` 以 root 启动，对 `/data`、`/app/logs` 与 `--log-dir` 指定目录做**可写性探测**（不是按属主判断；Docker Desktop 的 virtiofs 会把绑定挂载一律显示为 `0:0`），不可写才 `chown 1000:1000`，随后 `su-exec` 降权，服务进程始终以 uid 1000 运行。

- macOS：绑定挂载对容器内任意 uid 可写，探测直接通过，不产生 chown。
- Linux：宿主机目录属 root 时由入口自动接管属主。
- 只读挂载或 NFS root_squash 无法交接属主时才用 `NEW_API_RUN_AS_ROOT=1` 显式放弃降权，并写入批准记录。

验收：`docker top new-api -o pid,user,args | grep '/new-api'` 的 `USER` 必须是 `1000` 或 `newapi`。

### 1.5 反向代理与 TRUSTED_PROXIES（已决策：保持为空）

实测拓扑：Caddy 以宿主进程监听 `:3000`，`reverse_proxy 127.0.0.1:13000`；后端容器把 3000 发布在 `0.0.0.0:13000`。Caddy 会带上 `X-Real-IP` 与 `X-Forwarded-For`。

实测证据：`docker logs new-api --tail 2000` 的 `[GIN]` 行里，190 条请求的客户端地址都是 `172.24.0.1`（Docker 网桥网关），只有 7 条是 `127.0.0.1`。说明进程没有信任转发头，经 Caddy 的请求在限流与日志里全部塌缩成同一个地址。

可选项：

- `TRUSTED_PROXIES=auto`：容器内自动信任 loopback 与容器网段，网桥网关落在该网段内，转发头会被采纳。隔离环境已用该取值（`deploy/compose/dev-isolated.yml:66`）。
- 显式网关地址（如 `172.24.0.1`）：Docker 网络重建后网关可能变化，需要同步维护。
- 保持为空：与现状一致，限流与日志继续塌缩。

**决策（2026-11-04）：Caddy 暂未投入正式流量，`TRUSTED_PROXIES` 保持为空，本次升级不改变限流语义。`auto` 机制保留，未来正式接入反向代理时再切换。**

## 3. 已知风险

- **Compose 调用方式必须复现**：当前容器创建时使用 `docker-compose.yml` 加 `/tmp/new-api-prod-lite-override.yml`，后者已不存在。实测仅用 `docker-compose.yml + .env` 渲染通过（`docker compose config --quiet` 退出码 0），且运行中容器除 `PATH` 外没有 compose 未声明的变量；仍须在升级前把渲染结果与容器实际环境逐键比对。
- **76 个新增环境变量的默认值不等于当前行为**：已核对 `MEMORY_CACHE_ENABLED` 与 `CHANNEL_CACHE_SYNC_ENABLED` 会由"未设置"变为"true"，属行为变化，需要批准记录。

- **`./model` 偶发 shuffle 失败**：与本轮改动无关的既有偶发，发布门禁不依赖 `-shuffle`。
